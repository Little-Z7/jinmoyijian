# 运行环境与网页能力检查

本文件用于在操作官方网站前确认当前会话真正具备哪些网页能力。产品名称、已安装 Skill 或口头说明都不能证明工具已启用；必须以当前会话实际暴露且可调用的能力为准。

## 检查时机

- 每次调用本 Skill，并在首次操作意见表单前检查一次；即使用户已经手动打开意见页也不能跳过。
- 浏览器连接中断、登录状态变化、标签页被关闭或切换网页工具后重新检查。
- 不在后台持续轮询，不扫描无关应用、标签页、文件、Cookie 或账号信息。
- 安装成功只说明 Skill 可被读取，不代表具备网页控制、登录态复用或 Computer Use 能力。

## 能力分级

按实际能力而不是工具名称，将当前环境归入下面一种模式：

| 通道 | 就绪判据 | 使用规则 |
| --- | --- | --- |
| 已登录浏览器控制 | 能连接用户明确指定的现有 Chrome 等浏览器，并只读取得目标页 URL 与标题 | 用户要求复用登录态时优先；不检查 Cookie、密码或本地存储 |
| Browser Use | 当前会话存在可调用工具，且只读探测能取得实时 URL、可见文本和控件 | 使用语义定位，页面变化后重新读取；安装 Skill 不等于该工具已开启 |
| Computer Use | 能只读取得目标浏览器的实时应用状态 | 仅在结构化浏览器控制不可用时使用；每一步刷新状态，不依赖历史坐标 |
| Playwright 或其他隔离浏览器 | 工具可调用且能打开可见浏览器会话 | 明确说明不继承日常 Chrome 登录态；禁止保存、导出或迁移认证状态 |
| 人工协作 | 上述能力均不可调用 | 只提供入口、正文和核对清单，不声称已打开、预填、提交或验证成功 |

Browser Use、Chrome、Computer Use、Playwright 等名称只是线索。必须确认相应工具在**当前会话**可调用，并具备本任务需要的查看页面、定位控件、点击和输入能力。

## 预检步骤

1. 查看当前会话可用的工具、连接器或 Skills，判断是否存在上述网页能力；不要因为安装指南提到某产品就假定能力已经开启。
2. 若用户要求复用其已登录 Chrome，确认当前工具明确连接的是用户现有 Chrome 会话。只能启动新浏览器或应用内浏览器时，先说明它不会自动继承登录状态。
3. 只选择一种网页控制通道和一个活动标签页。不要让 Browser Use、Computer Use 或多个代理同时操作同一表单。
4. 用无副作用的只读动作验证连接：读取当前标签页 URL 与标题，或打开官方入口后读取可见标题。验证失败不算就绪。
5. 报告所选模式、是否能复用登录态以及需要用户接管的步骤，再开始 [site-workflow.md](site-workflow.md) 中的页面核验。

若当前能力只能搜索网页或读取公开网页文本，不能与表单控件交互，应归入人工协作模式，不能把只读 Web Search 当成 Browser Use。

## 能力未启用或未连接

如果能看出相关能力已安装但处于关闭、未连接或未授权状态：

- 明确说明缺少的是浏览器控制、现有 Chrome 连接还是 Computer Use，不笼统声称“环境不支持”。
- 只依据当前产品实际可见的设置、工具、连接器或 Skills 页面给出开启步骤；看不到入口时请用户打开相应设置，不能猜测隐藏开关、虚构菜单或要求关闭安全机制。
- 引导语可使用：`当前会话还没有可用的网页控制能力。请在本产品的工具、连接器或 Skills 设置中启用 Browser Use、浏览器控制或 Computer Use；若没有这些入口，我可以切换为人工协作模式。`
- 用户完成开启或连接后，重新执行一次只读验证。仍失败时停止自动操作并提供人工协作步骤。
- 不擅自安装浏览器扩展、连接账号、改变隐私权限或开启远程控制；这些动作需要用户明确决定并按产品权限提示完成。

## 敏感阶段接管

- 个人信息页、登录页和验证码页由用户完整接管，包括点击会发送数据的“进入”“登录”“下一步”等控件。
- 接管期间，所有网页通道都停止读取页面、截图、快照、录屏、trace、控制台和网络日志；不要观察自动填充结果。
- 用户应自行完成输入并离开含敏感字段的页面，再明确告知助手继续。恢复后只核对 URL、页面标题及不含个人信息的状态，不回读敏感字段。
- 不因改用 Computer Use、Playwright 或另一个标签页而降低这些要求。

## 登录状态失效

- 官方页面显示登录过期、会话失效或跳回登录页时，仅在尚未进入提交阶段、页面没有待保存表单内容且刷新不会重新发送 POST 的情况下，才可对当前官方页面做一次普通刷新并重新读取页面状态。
- 出现“重新提交表单”警告、已有填写内容或提交状态不明时不得刷新。
- 一次刷新后仍需登录时，立即交给用户本人完成登录；不要连续刷新、脚本化登录或尝试从其他浏览器搬运会话。
- 不读取、复制、导出、记录或修改 Cookie、访问令牌、本地存储、请求头和密码管理器内容；也不得使用 `storageState`、状态保存文件或复制浏览器配置目录来迁移登录态。
- 用户完成登录后，重新核对主机名、草案标题、征求意见期限、表单内容和当前提交状态。登录状态变化会使此前的最终提交确认失效。

## 人工接管与降级

- 姓名、联系方式等个人信息，以及图片验证码、短信验证码和其他人机验证，始终由用户直接操作；网页工具是否可用不改变这一边界。
- 任何网页通道出现个人信息或验证码时都不转录、不截图、不回显；请用户接管，待其离开敏感页面并明确告知完成后再重新核对非敏感页面状态。
- 没有网页控制能力时，按人工协作模式给出当前一步的页面位置、需核对的标题或条款、待填意见正文和提交前检查项。不得把“提供步骤”说成“已经预填”或“已经提交”。
- 工具切换、页面刷新、重新登录或用户手动修改表单后，必须重新读取非敏感字段状态；任何旧的提交确认均不得沿用。

## 行为验收场景

维护或移植本 Skill 时，至少验证以下情形：

- 能连接用户指定的已登录 Chrome：使用该会话，只读验证连接，不检查或导出认证数据。
- 只有隔离 Playwright 或应用内浏览器：说明不继承 Chrome 登录态，登录步骤由用户完成。
- 只有 Computer Use：逐步读取实时画面，敏感页面完整交接，不使用历史坐标提交。
- 没有网页控制：给出人工步骤，不声称已打开、预填、提交或验证成功。
- 页面为 HTTP、证书异常或表单目标不明：不在网页内输入任何内容，不代点发送控件。
- 出现验证码或个人信息：停止所有可能记录页面的能力，待用户离开敏感页面后再继续。
- 登录过期且页面已有草稿或可能重发 POST：不刷新，由用户决定如何保存和重新登录。
- 提交按钮无响应或结果不明：不重试、不换工具再次点击，只报告无法确认。
